## Goal

Split code review's two responsibilities along "correctness vs security/deep-issues" and reassign executors:

- **Orchestrator inline gate (correctness)**: the `/gal pipeline` session itself, on receiving the implement result, uses its full plan context to confirm "did this code correctly complete `T-NNN`" — functional correctness, architecture fit, code quality, obvious performance. **Not dispatched**; it is a gate between implement and test; only on pass does it proceed to TESTER.
- **golem-auditor (deep + security, always dispatched)**: a single audit specialist merged from `golem-reviewer` and `golem-security`, owning deep performance + all security review, promoted from conditional to **per-task constant**.

Done when:
1. `golem-security` is renamed/expanded to `golem-auditor`, `golem-reviewer` is deleted, no dead references remain.
2. Pipeline phases: implement → **orchestrator correctness gate** → test → **auditor (constant)** → verify; the dispatched REVIEWER phase is removed.
3. The responsibility split is documented: orchestrator does checklist 1–13 + obvious performance; auditor does deep performance + security (14–23).
4. Routing key `REVIEWER` → `AUDITOR`; dispatch phase key `review` → `audit`; all references updated or regenerated by `gal sync`.

## Review Results

### Architecture Review

**Verdict: APPROVE-with-conditions** *(2026-06-10 full deep-planning)*

Directionally correct: "is it correct" is a cheap judgment the orchestrator already has full context for, and dispatching it out throws that context away; "deep + security" needs an independent view and a focused checklist, and making it constant removes the conditional-trigger judgment gap (R-06 review evidence: the trigger judgment for security-sensitive changes itself misses). The merge eliminates reviewer/security responsibility overlap (boundary conditions and performance were claimed by both).

**Conditions (binding at implementation):**
- **C1 no security downgrade**: golem-security's STOP rule (high/critical open → stop) is preserved verbatim into auditor; the migration commit diff must show no semantic deletion.
- **C2 atomicity of the clean cut**: the stage.rs phase key, gal-pipeline SKILL, agentMap, and routing example all land in **one commit**; no intermediate commit may have "skill emits audit but bin only knows review".
- **C3 independence reinforcement documented**: coding.md rewrite spells out the three-layer independence (auditor dispatch, TESTER≠CODER, VERIFIER≠CODER) + architect sign-off on protected paths; the correctness gate is positioned in writing as an "early catch" to prevent it from later being misread as an independent-review replacement.
- **C4 machine-local routing migration guidance**: on an unrouted `audit` phase, the dispatch message must explicitly say "the `REVIEWER` key was renamed `AUDITOR`, update ~/.gal/config/executor-routing.json" — not merely report no-routing.
- **C5 ordering dependency**: this plan changes `New-TaskSpec.ps1` only after small-context lands (D-3); if small-context is delayed, the agentMap change may go first but must be listed in its rebase checklist.

**Trade-off Summary**

| Decision | Benefit | Cost | Verdict |
| --- | --- | --- | --- |
| correctness gate into orchestrator | full-context judgment, saves a dispatch, early catch | no independent view when implement is inline | OK (D-1 accepted + C3 reinforcement) |
| merge reviewer+security | eliminate overlap, single audit entry | one agent's checklist grows | OK (checklist 14–23 focused) |
| auditor made constant | removes the conditional-trigger miss | one dispatch per task | OK (YAGNI threshold added later) |
| clean phase-key cut, no alias | zeroed, no residue, single semantics | machine-local routing needs manual follow-up | OK (C4 guidance) |

**Bug Surface**: intermediate-state gap (C2 atomicity); machine-local routing missed (C4); security-checklist semantics lost (C1).
**Over-engineering check**: no alias layer, no complexity threshold, no new store — the minimal surface holds.
**Performance**: one extra auditor dispatch per task replaces the original conditional REVIEWER dispatch (net ≈0, since the original REVIEWER dispatched every task too); the real net change is the conditional-security → constant increment, which is bounded.
