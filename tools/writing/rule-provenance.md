# Writing toolchain provenance

This workspace is the repository-owned, development-only textlint toolchain. Installations are explicit and lockfile-based. Normal GAL operation does not download npm packages.

## Runtime and parser

| Component | Exact version or range | License | Source and ownership |
| --- | --- | --- | --- |
| Node.js | `>=20.0.0` | Node.js license | Runtime range declared by `package.json`; the workspace owns this compatibility contract. |
| `textlint` | `15.2.3` | MIT | [textlint](https://github.com/textlint/textlint); GAL owns the pinned CLI and official `--mcp` route. Version `15.2.0` or later is required because MCP accepts `--config` with the MCP flag from that release. |
| Markdown parser | Bundled by `textlint@15.2.3` | MIT | textlint's built-in Markdown parser; GAL does not add a second parser package. |

The official MCP interface is `textlint --mcp`. The `mcp` npm script exposes that interface. Select a trusted locale profile and pass its JSON path through `--config`; the MCP caller must not rely on inferred locale selection. See [README.md](README.md) for setup commands and examples.

## Enabled rule roster

The fixed roster below records package implementation licenses separately from the policy-document licenses in the next section. All three locale profiles enable the GAL terminology rule. Its implementation is repository-owned and reads executable term data built from the terminology authorities. The rule owns project terminology, forbidden forms, and invalid or conflicting term data. Forbidden forms are hard findings except for entries whose presentation mode is `contextual`, which remain advisory. First-use presentation findings are also advisory. Invalid or conflicting term data causes an operational failure. The terminology-data fields for `schemaVersion=1` are documented in [README.md](README.md#terminology-data). The check report is a separate data structure.

The `passive` policy adapts active-voice guidance from Google and Microsoft. The `tooWordy` policy adapts concise-wording guidance from Google and Microsoft. These adaptations do not claim equivalence with Vale rules. The `zh-TW` profile initially uses deterministic terminology checks only. An optional zhtw-mcp check may add regional or grammar advice later. It is not a second punctuation policy. pangu and Vale are not dependencies because no tested gap authorizes them.

## Adapted policy sources

The policy sources below provide guidance only. Their content licenses do not replace the MIT licenses of the npm rule implementations. GAL records the retrieved date when an upstream page does not expose a revision date.

| Adapted policy | Upstream source | Upstream revision identifier | Content license | GAL adaptation and ownership |

GAL owns the adaptation. |
| Concise wording | [Google Word list: in order to](https://developers.google.com/style/word-list#in-order-to) | Last updated `2026-08-25 UTC`; retrieved `2026-10-01` | CC BY 4.0; Google Developers page terms | Prefer `to` when it preserves meaning. | Active voice and verb choice | [Microsoft Verbs](https://learn.microsoft.com/en-us/style-guide/grammar/verbs) | Last updated `2025-03-24` | CC BY 4.0; Microsoft Learn content license | Prefer active voice and precise verbs; keep documented passive-voice exceptions for errors, receiver emphasis, and awkward constructions. GAL owns the adaptation. |
| Concise wording | [Microsoft Use simple words, concise sentences](https://learn.microsoft.com/en-us/style-guide/word-choice/use-simple-words-concise-sentences) | Last updated `2022-06-24` | CC BY 4.0; Microsoft Learn content license | Prefer simple, precise words and remove words that add no substance; report guidance only and do not auto-fix. GAL owns the adaptation. |

The fixed examples and planned test-file mappings above are the executable-policy handoff for later configuration and test tasks. They do not create tests in this task.

Upgrades must not silently enable disabled subrules or change advisory rules into automatic fixes. Any version change requires an update to this file and a new lockfile.
