# 統合

[English](../../integrations.md) · **日本語** · [繁體中文](../zh-Hant/integrations.zh-Hant.md)

本ドキュメントは、オプションとして利用可能な外部ツール統合に関するリファレンス仕様です。ここに挙げるツールはいずれもオプションであり、GAL のコア機能の動作に必須のものはありません。これらのツールがインストールされていない環境でも、GAL は問題なく完全に機能します。5 段階の事前確認（preflight check）、構造取得のルーティング、グレースフルデグラデーション（機能低下時の安全な縮退動作）を含む正式な運用規則は [`plugins/gal-core/conventions/optional-capabilities.md`](../../../plugins/gal-core/conventions/optional-capabilities.md) に定義されています。本ドキュメントでは、各統合に関する前提知識と運用上の境界を提示します。

以下の各セクションでは、運用目的、GAL 内の利用者、準備状況の検証、設定境界、フォールバックの挙動、統合の所有権について解説します。

## オプション統合マトリクス

| 統合 | 目的 | 不在時のフォールバック動作 |
| --- | --- | --- |
| `codebase-memory-mcp` | コードシンボルおよび構造グラフの検索 | ネイティブの `git diff` と対象を絞ったファイル読み込みにフォールバックします。 |
| `graphify` | 事前生成されたコードベース知識グラフの活用 | ソースファイルの直接読み込みにフォールバックします。 |
| `OpenCLI` | 低トークン消費での構造化外部データ取得 | 標準の Web 取得ツールにフォールバックします。 |
| `Playwright MCP` | 対話的なブラウザーテストと視覚的検証 | 成功を偽装することなく、機能不足を明示して処理を停止します。 |

### codebase-memory-mcp

- **目的**: 構造的なシンボル検索および知識グラフ探索を提供するオプションの Model Context Protocol（MCP）サーバーです。初期の `git diff` 検査後に、シンボル単位での変更影響範囲の特定を精密化します。
- **GAL 内の利用者**: `codeRefs` に `#symbol` アンカーが指定されている場合に、`doc-sync` が影響を受けるドキュメントを特定するために利用します。また、`graphify` 実行後の 2 次構造探索ツールとしても利用されます。
- **準備状況の確認**: MCP サーバーと通信可能であり、`index_status` によって対象リポジトリのインデックスが作成済みかつクエリ可能であることが確認できる必要があります。Codex では、設定済みサーバー一覧ではなく、現在のセッションに実際に公開されているツール一覧で判定します。設定が存在してもセッションに公開されていない場合は `unavailable`（利用不可）として扱います。
- **設定境界**: GAL が `codebase-memory-mcp` のインストール、設定、またはリポジトリの自動インデックス作成を行うことはありません。ツールの導入、インデックス作成のスケジュール管理、クエリセマンティクスの維持は、すべてアップストリーム側の責務です。
- **安全なフォールバック**: ネイティブの `git diff` および直接のファイル検査が基本の動作基盤となります。MCP クエリはファイル単位の調査結果を補強・精密化するものであり、基本的なファイル検査を完全に代替するものではありません。
- **統合の所有権**: 消費のみ（Consumed only）。プロジェクトの基本方針により、`plugins/gal-core/mcp.json` のサーバーマニフェストは既定で空になっています。本統合を有効化する場合は、標準の `"servers"` スキーマを用いて `~/.gal/local/mcp.json` に登録するか、ホストランタイム側の MCP 設定に直接記述してください。

### graphify

- **目的**: CLI 駆動のアーキテクチャコンテキストエンジンです。事前に生成されたグラフ解析レポート（`graphify-out/GRAPH_REPORT.md`）を読み込み、ゴッドノード（god node）、モジュールコミュニティ、予期せぬ結合度などの構造的文脈を計画策定やレビューに提供します。
- **GAL 内の利用者**: `/planning` および `/deep-planning` における境界分析、`golem-architect` による変更影響範囲（blast radius）の評価、`golem-auditor` による境界横断的な変更監査で参照されます。
- **準備状況の確認**: リポジトリルートに `graphify-out/GRAPH_REPORT.md` が存在する必要があります。`graphify-out/GAL_GRAPHIFY_VERSION.txt` が存在する場合、その内容を `graphify --version` と比較して成果物の陳腐化を判定します。バージョンが異なり、かつレポートのタイムスタンプが更新されていない場合は、古いレポート（stale）として扱います。
- **設定境界**: GAL が graphify のインストール、グラフの構築、陳腐化したレポートの自動再生成を行うことはありません。グラフの生成およびツールのメンテナンスは外部の責務です。[safishamsi/graphify](https://github.com/safishamsi/graphify) を参照してください。
- **安全なフォールバック**: ソースファイルの直接検査および標準の計画ワークフローへ安全に戻ります。グラフファイルが存在しない場合でも、エラーを出力したりセットアップを要求したりすることはありません。
- **統合の所有権**: 生成ファイル成果物の消費のみ（Consumed file artifact only）。MCP サーバーとしては設定されず、GAL は生成されたレポートファイルをパースするのみで、対話的に graphify を実行することはありません。

### OpenCLI

- **目的**: YouTube、NotebookLM、Wikipedia、Hacker News、Google News などから、トークン消費を抑えつつ構造化データを取得するためのサイトアダプター対応外部 CLI ランタイムです。
- **GAL 内の利用者**: 調査ワークフロー（`/gal research`、`/gal deep-research`）および `opencli-research` スキルから呼び出されます。
- **準備状況の確認**: `opencli --version` コマンドが正常に実行でき、実行中のタスクに対応するアダプターが存在し、要求されたデータフィールドをサポートしている必要があります。
- **設定境界**: GAL が OpenCLI 本体や各種サイトアダプターをインストールすることはありません。ツールの導入やアダプターの設定は、ユーザーが独立して管理します。
- **安全なフォールバック**: 標準的な Web ページに対しては MCP の `fetch` または `imagefetch` ツールを使用します。リッチな描画やインタラクティブな操作が必要な場合は Playwright MCP または Chrome DevTools MCP へフォールバックし、ローカルファイルに対してはワークスペースのツールを使用します。必要なツールが利用できない場合は、機能の不足を明示して処理を安全に停止し、成功を装うことはしません。
- **統合の所有権**: 外部 CLI 実行ファイルの消費のみ（Consumed CLI executable only）。MCP マニフェストには登録されません。

### Playwright MCP

- **目的**: 実ブラウザーでの Web ナビゲーション、アクセシビリティツリーのスナップショット取得、レスポンシブレイアウトの検証、DOM 構造の検査を提供するブラウザー自動化サーバーです。
- **GAL 内の利用者**: `golem-tester` による UI 回帰テストの自動化、`golem-designer` による視覚的監査、および動的な JavaScript 実行を伴う調査タスクで利用されます。
- **準備状況の確認**: ホストランタイムが Playwright MCP サーバーを正しく解決して起動でき、ブラウザーの初期化が完了し、ブラウザー互換の対象 URL を受け取れる状態である必要があります。
- **設定境界**: GAL がテスト、レビュー、調査などのタスク実行中に、ブラウザーのバイナリダウンロードやランタイムのインストールを勝手に開始することはありません。
- **安全なフォールバック**: 詳細なネットワークやパフォーマンスの診断には Chrome DevTools MCP を使用し、反復実行可能なテストスクリプトにはスタンドアロンの Playwright テストランナーを実行します。基本的なテキスト取得には OpenCLI、Defuddle、またはワークスペースツールを使用します。実ブラウザーによるアサーションが成功しない限り、エージェントがブラウザー検証を「パス（成功）」と虚偽報告することは禁止されています。
- **統合の所有権**: ユーザー接続型の統合（User-wired integration）。Playwright MCP はコアプラグインのマニフェスト（`plugins/gal-core/mcp.json`）には含まれておらず、ユーザーがホストランタイム側で直接設定します。

### textlint による文章チェック

- **目的**: リポジトリが所有し、バージョンを固定した textlint ワークスペースで、英語、台湾繁体字中国語、日本語の文章を検査します。これは開発ツールです。インストール済み GAL のコピーや下流リポジトリに、この Node ワークスペースは必要ありません。
- **プロファイル**: 明示的なロケール指定、対応するフロントマターの最上位 `lang` 文字列、既知の管理対象パスの順に解決します。wrapper は `en`/`en-US`、`ja`/`ja-JP`、`zh-TW` を受け付けます。`zh-Hant` を `zh-TW` に対応付けるのは、管理対象の `docs/i18n/zh-Hant/` ファイルだけです。未知のパスに有効な指定やメタデータがなければ、運用上の失敗になります。不正なメタデータからパス判定へ暗黙に切り替えません。有効な明示指定は、使用しないメタデータより優先します。仮想ファイル名は stdin の識別と解析に使い、ロケール選択には使いません。
- **CLI**: 本リポジトリのルートから `node tools/writing/check.mjs --files <paths...>` を実行します。別の文書ルートを検査する場合は、そのルートを作業ディレクトリにし、信頼できるインストール済み `check.mjs` の絶対パスを指定します。明示的な指定が必要なら `--locale <locale>` を付けます。`node tools/writing/check.mjs --required` は追跡対象の文書ごとにロケールを選びます。必須モードでは全体を上書きするロケール指定を拒否します。固定パッケージは `npm ci --prefix tools/writing` で明示的にインストールします。通常の GAL 作業ではパッケージをダウンロードしません。
- **完全な MCP レポート**: wrapper の `--files` より前に `--transport mcp` を追加します。`--required` とも併用できます。既定の経路は `cli` です。両経路は同じ形式の指摘と実行の出典情報を保持し、ハンドシェイクが成功した場合は MCP レポートに公式サーバーの識別情報も記録します。以下のネイティブ CLI/MCP コマンドは低レベルの診断インターフェースであり、完全な GAL レポートは返しません。MCP のスキーマ検証、タイムアウト、終了処理の失敗は運用上のエラーで、終了コードは `2` です。
- **公式 MCP**: 呼び出し元は同じ優先順位でロケールを解決してから、信頼できる JSON `--config` とルールディレクトリを明示して固定版 textlint MCP を起動します。リポジトリの JavaScript 設定を渡してはいけません。呼び出し元は stdin の仮想ファイル名も指定します。MCP はロケールを推測せず、パッケージの取得、文章修正、入力変更もしません。
- **用語データ**: wrapper は文書ルートの `.dev/cache/writing-terms/<sourceHash>.json` に不変データを生成し、そのハッシュを子プロセスに渡します。直接 CLI/MCP を使う場合は、先に自身の文書ルートを作業ディレクトリにして `node <absolute-path-to-terms.mjs>` を実行し、一致するスナップショットを使用します。追加の環境設定は不要です。欠落、破損、古いスナップショットは運用上の失敗になります。単一のツール環境から複数の文書ルートを検査しても、共有の可変データを置き換えません。
- **指摘の責務**: GAL の用語権威がプロジェクト用語を管理し、補足的な地域表現の助言より優先されます。textlint は設定済みのプロジェクト検査を担当します。任意の `zhtw-mcp` は地域表現、翻訳調、文脈に関する指摘を補足できます。GAL の用語検査を置き換えたり、別の句読点ポリシーを作ったりしません。`accurate-answer` は個人向けの参考資料であり、GAL の要件や依存関係ではありません。
- **ホストの制約**: 人向けの全メッセージで作成中の自己レビューを行います。設定済みのチェッカーが利用可能なら、送信前の草稿も検査します。出力の遮断は、ホストの直接的な証拠がある場合だけ主張します。ファイル検査では送信済みの会話を調べられません。任意のチェッカーが利用できない場合も自己レビューを続け、利用可能性または配信への影響が変わるまで制約の通知は 1 回にします。必須ゲートはハード指摘や運用上の失敗で停止します。別の明示的な必須条件がない限り、助言だけでは停止しません。
- **信頼とプライバシー**: 信頼できるリポジトリ管理下の JSON プロファイルとローカルの固定ルールだけを実行します。リポジトリの JavaScript 設定を実行したり、ルールを自動インストールしたりしません。stdin で渡すチャット草稿は内容であり、コマンドや指示ではありません。チェッカーは既定でチャット本文を保存しません。任意の `zhtw-mcp` 外部検査は呼び出し元が明示的に有効にします。送信した文章が同サービスへ転送される場合があります。
- **結果**: 検査結果は重大なエラー、助言、運用上の失敗を区別します。指摘がない結果でも、意味の同等性や読みやすさを証明するものではありません。チェッカーは入力を自動で書き換えません。コマンドとレポートの詳細は [tools/writing/README.md](../../../tools/writing/README.md) を、ポリシーの責務は [writing-quality.md](../../../plugins/gal-core/conventions/writing-quality.md) を参照してください。

外部ノートストレージ（`local-notes`）は、第三者ツールの統合ではなくユーザー所有の個人インフラストラクチャとして位置付けられています。拘束力を持つ行動規範については [`optional-capabilities.md`](../../../plugins/gal-core/conventions/optional-capabilities.md) を、具体的な設定手順については [設定](configuration.ja.md#外部ノート統合local-notes) を参照してください。
