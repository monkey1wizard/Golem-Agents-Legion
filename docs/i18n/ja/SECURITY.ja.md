# セキュリティポリシー

## サポート対象バージョン

セキュリティ更新は最新リリースに対してのみ提供されます。過去のリリースに対するセキュリティ修正のバックポートは実施しません。

## 脆弱性の報告

脆弱性の報告は、GitHub Private Security Advisories を通じて非公開で行ってください。脆弱性が疑われる場合でも、公開 Issue は作成しないでください。なお、本プロジェクトには専用のセキュリティ連絡用メールアドレスはありません。

メンテナーは脆弱性の開示と修正パッチのリリース調整に最大限努めますが、特定日数以内の対応（SLA）を保証するものではありません。報告を受領後、メンテナーは影響範囲（blast radius）を調査し、修正を作成した上で、Advisory 内で協調的な情報開示（Coordinated Disclosure）のスケジュールを設定します。

## セキュリティモデル

### 保護対象の資産

GAL が保護対象とする主な資産は次のとおりです。

- `gal init` によって生成される `AGENTS.md` および `CLAUDE.md`
- 投影（projection）されたスキル、コマンド、golem エージェントの定義
- `~/.gal/config/config.json` に格納されるマシンローカル設定
- `~/.gal/local/` 配下のユーザーファイル
- `.dev/` 配下に保持されるリポジトリ所有の状態ファイル

### 信頼モデルとロール

ローカルの操作者（オペレーター）は信頼できるエンティティとして扱われます。リリースのサプライチェーンは、`checksums.txt` に記載された SHA-256 ハッシュおよび Cosign のキーレス署名（keyless cosign signature）によって検証されます。一方、ディスパッチされたエグゼキューター（executor）、エグゼキューターからの write-back ペイロード、インポートされた計画やプロンプトは、すべて信頼できない入力（untrusted input）として扱います。ホスト側の MCP 設定はユーザーが所有するものであり、`gal` が明示的な指示なくホスト設定を改変することはありません。

### 信頼境界

- **所有権マーカー**: GAL の所有権マーカーにより、Git で追跡される契約ソースと自動生成されるアダプターを明確に分離します。既存ファイルにこのマーカーが存在しない場合、変更処理は直ちに中止されます。
- **状態の分離**: `_galProjection` 名前空間により、GAL が管理する状態と外部の状態を分離します。GAL は `plugins.lock.json` 内の他のトップレベルキーを操作しません。
- **インライン化された契約**: 契約バイト列をインライン化することで、コントロールノードとリモートエグゼキューターを疎結合に保ちます。エグゼキューターがコントロールノード上にしか存在しないパスを直接参照することはありません。
- **ローカル設定**: `~/.gal/config/config.json` は厳格にマシンローカルな設定ファイルです。`executorRouting`、`sshTarget`、`remoteWorkdir` の設定値をリポジトリへコミットしたり、マシン間で共有したりしてはいけません。
- **Codex ホストポリシー**: Codex の承認ポリシーおよびサンドボックス設定は、ユーザーが管理するホスト側の設定であり、GAL がこれらを変更することはありません。親セッション側で操作を承認した場合であっても、ディスパッチされた子プロセスの `workspace-write` サンドボックスが緩和・解除されることはありません。拒否された操作を承認済みとして扱うことはなく、観測不能なポリシー状態は一貫して Unknown（不明）として扱われます。
- **実行証拠**: 実行ファイルの探索（availability lookup）、プロセスの起動、プロバイダーの応答、プロセスの終了、レシートの検証、およびパイプラインゲートの評価は、それぞれ独立した証拠段階です。ある段階で失敗したとしても、それが後続段階の結果を意味したり決定づけたりすることはありません。診断出力では試行した操作を特定できるようにしつつ、パスや機密情報をマスキング（秘匿）する必要があります。設定ファイル、環境変数の内容、認証トークン、資格情報を診断ログへダンプしてはなりません。

### セキュリティ不変条件

アダプターのレンダリング時は必須セクションを検証し、構文エラーやスキーマエラーが発生した場合は fail-closed（安全側に倒して処理を中断）します。ファイルの書き込みおよび削除には有効な所有権マーカーが必要であり、GAL の管理下にあるパスのみが削除対象となります。計画スコープのクリーンアップは正常終了が必須であり、失敗した場合は failure receipt（失敗レシート）を記録します。Git の pre-commit フィルターと `gal doctor` のシークレットスキャンは、同一の正規表現（`secret_re`）を共通で使用します。インストーラーは SHA-256 チェックサムまたは Cosign 署名の検証に失敗した場合、直ちに実行を中止します。Codex のセットアップおよび復旧手順については [セットアップ](setup.ja.md#codex-パイプライン実行のセットアップ) を参照してください。アーキテクチャの詳細仕様については、[アーキテクチャ](architecture.ja.md)、[プロジェクション](projection.ja.md)、[設定](configuration.ja.md)、[ワークフロー](workflows.ja.md) を参照してください。

### 攻撃対象領域

主な攻撃ベクトル（侵入経路）には、信頼できないエグゼキューターからの入力や write-back データ、外部からインポートされた計画ファイルやプロンプトファイル、`config.json` で定義された SSH 実行レーン、MCP ホスト読み込み時の環境変数展開（`${ENV_VAR}`）、およびリリース成果物のダウンロードが含まれます。なお、`ready-to-finalize` が提供するのはワークフロー協調上のエビデンス（証跡）のみです。暗号学的な出所証明（provenance）を提供するものではなく、ローカルの書き込み権限を持つ攻撃者からの改ざんを防ぐものではありません。

### ローカルセキュリティツール

ローカルのセキュリティレビュープラグインは一般的な脆弱性の早期検出に役立ちますが、必須の依存関係ではなく、マージをブロックする必須要件でもありません。レビューツールによって本ドキュメントで定義された信頼境界に関わる問題が検出された場合、対応するセキュリティ不変条件に従って必要な是正措置を講じます。ハードコードされたシークレットの検出は `secret_re` チェックが担います。また、アダプター所有権マーカーの整合性、エグゼキューターの write-back 処理、`config.json` における SSH ルーティング、インポートされた計画ファイルなどは、重点的なレビューを要する GAL 固有のリスク領域です。リリース版で脆弱性を発見した場合は、前述の非公開 Advisory 窓口からご報告ください。
